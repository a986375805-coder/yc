GamePulse AI · 游戏节点聚合中台

展开/收起

把编辑团队「翻多个平台找游戏测试节点」的手工活，变成一条自动流水线：定时爬取 → LLM 结构化 → 入库 → 可视化。不止做了个脚本，而是做成团队每天打开的生产工具。

我做了什么

  • 从编辑手动操作里识别需求：跨平台数据分散 + 人工判断口径不一，是效率与准确率的双重瓶颈。
  • 技术选型：对比 RPA 后选择「爬虫 + LLM」，因为不同平台页面结构差异大，RPA 维护成本高且无法语义理解「公测 / 内测 / 新版本」这类判断。
  • 质量兜底：「AI 初筛 + AI 复检」双模型交叉验证 + 每一条数据保留来源链接可一键回溯，把不可靠交给流程而非运气。
  • 产品化：做日历视图、四栏看板、测试排期表、只读分享页，非技术同事也能直接用。

关键成果

90%+判断准确率（初筛+复检+溯源）
67–83%编辑录入效率提升
生产在用替代原手动流程并持续迭代

PC 端改版 · 需求文档

游戏详情页改版需求设计

展开/收起

基于用户行为数据，把承载信息日益庞杂的 PC 详情页，重构成「资源再分配」的双栏布局。已输出完整 PRD 并推进到开发。

问题判断

首屏缺乏站内优质资源（如独家报道）的有效曝光；用户要滚动多次才能找到关键信息。瓶颈在布局结构，而非单纯增加内容。

全局布局

总宽 1210px 双栏：左侧主干区 860px 承载媒体物料与内容流，右侧侧边栏 320px 承载游戏信息与转化插卡；两栏间 30px 间距。

响应式机制

＞1400px 完整展示；1000–1400px 内容区等比例收纳、侧边栏固定；最窄 1000px。断点细节交由前端调优，原型期先定规范。

模块动线

按「用户决策路径」组织：先看媒体物料 → 再查基础信息（右侧首屏转化区）→ 后看口碑长尾。让用户更快进入下载 / 预约决策。

新增模块

游戏信息分发插卡（首屏转化）、资讯 Banner（站内优质内容曝光）、游戏历程插卡（版本追踪）、基本信息插卡（多列 + 空值隐藏 + 外链另起行）。

设计产出

  • 完整 PRD：页面全局布局规范、插卡分布表、响应式机制、模块交互逻辑。
  • 墨刀高保真原型：含右侧游戏信息分发插卡样式与交互、资讯 Banner、游戏历程插卡、吸顶 Tab 与底部悬浮分发栏。
  • 数据路径梳理：每个前端字段对应后台位置与字段，形成可落地的数据契约。
后台功能 · 需求文档

游戏历程插卡 · 后台配置功能设计

展开/收起

配合详情页「游戏历程插卡」前端模块，设计后台「测试信息管理」的新增配置能力，让运营能自助控制节点展示样式。输出完整需求说明并推动研发。

核心：样式联动状态机

根据「测试类型」自动约束「插卡样式」可选范围——封测 / 内测 / 日常更新锁定为「不设置」；新版本 / 公测 / 资料片开放「默认样式」与「图文样式」。把复杂的业务规则收敛成一张状态机，避免脏数据。

前端分发规则

仅拉取「公测 / 新版本 / 资料片」且开启样式的数据；按测试时间倒序，横向最多展示 4 个最新节点，其余收纳进「历史节点」浮窗。

表单字段

一句话说明（按样式区分必填 / 选填）、节点宣传图（图文样式必填）、内容标签页（2 字分类标签 + 自定义小标题 + 详细文本，1–6 组可增删）。

存量数据兼容

历史公测 / 新版本节点默认置「不设置」并继承原说明，避免存量异常文案直接外露；热门游戏调整完再统一放开。

交互细节

组数达上限后添加按钮置灰、仅剩 1 组时删除置灰；带兜底折叠逻辑——说明为空时前端隐藏灰底卡片仅保留时间轴。

体现的能力

  • 把模糊业务规则抽象成状态机与可执行逻辑，而非让研发猜。
  • 前后端一起设计：数据过滤、排序截断、兜底策略都写在需求里。
  • 考虑存量数据与灰度节奏，方案可直接落地。
